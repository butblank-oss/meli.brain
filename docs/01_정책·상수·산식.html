2. 참여일 정의 (F-01)

아래 세 가지 중 하나라도 기록이 있는 날의 합집합. KST 자정 경계로 날짜를 계산하고, 같은 날 여러 건이 있어도 1일로 집계합니다. 사용자별로 다른 기준을 쓰지 않으며 전원 동일 규칙입니다.

  1. 완료 활동 ≥ 1건 — S1 outcome_raw · activity_date_kst
  2. 로그인 ≥ 1건 — S8 login_history · is_success='Y'
  3. 걸음 > 0보 — S7 step_count · stat_date
참여일 = COUNT(DISTINCT (S1.activity_date_kst ∪ S8.login_date_kst ∪ S7.stat_date))
WHERE 날짜 BETWEEN 2026-03-03 AND 2026-10-30 (KST)

초안은 걸음 ∪ 로그인 2항이었습니다. 완료 활동을 3항으로 추가한 이유는 걸음 미연동자(3.3%)가 게임 · 마음 활동을 해도 참여일이 0으로 집계돼 구조적으로 불리했기 때문입니다. S7에는 0보 행이 생성되지 않으므로 "걸은 날 수 = 행 수"이며 0 제외 필터는 불필요합니다.

분모 242일이 "평일 수"가 아닌 이유 — 프로그램은 평일 편성이지만 분모는 평일만 센 값이 아닙니다. 마지막 프로그램일이 10/30(금)이라 종료일을 거기에 맞췄고, 3/3부터 10/30까지의 달력 일수가 242일입니다. 참여일 쪽도 주말 로그인 · 걸음을 그대로 세므로 분자와 분모의 기준이 서로 맞습니다. 평일만 세는 곳은 요일별 참여율(F-07) 하나뿐이고, 거기서도 분모는 "기간 내 그 요일이 실제로 몇 번 있었는가"입니다.

4-3. 선택 규칙

  • 거리 — 총 거리 이하인 지점 중 가장 먼 곳을 고르고 N = FLOOR(총거리 ÷ 편도)를 계산합니다. N에 따라 문구가 달라집니다.
  • N = 1 → "…까지 걸었어요" (회차를 쓰지 않습니다. "부산까지 1회 걸었어요" 금지)
  • N = 2 → "…까지 왕복했어요"
  • N ≥ 3 → "…까지 N회 걸었어요"
  • 예: 714,200보 → 464km → 420km 이하 최대인 부산 → N=1 → "서울에서 부산까지 걸었어요"
  • 칼로리 — 구간 경계는 인접 두 기준값의 중간점입니다. "사과 반 개" 같은 분수 표기가 나오지 않도록 항상 1개 단위로 떨어지게 잘랐습니다. 예: 3,607보 → 약 144kcal → 초코파이 하나 구간(138–185).
  • 기준값은 대표 열량이므로 "{음식}만큼"은 근사 표현입니다. 정확한 열량을 주장하는 문구로 바꾸면 안 됩니다.
  • 총 걸음이 7km(약 10,770보)에 못 미치면 첫 구간에도 들지 못합니다. 이 경우 거리 환산 카드를 감춥니다 (P17과 동일 처리).

5. 수료 분기 A / B / C

SC-RP-07의 문구 · 버튼 구성만 분기됩니다. SC-RP-01 ~ 06의 레이아웃은 분기와 무관하게 동일하며, 값이 없는 항목만 개별 P코드 규칙을 따릅니다. 즉 "미참여자용 별도 화면"을 만들지 않습니다 — 화면 구조는 하나이고 값만 달라집니다.

분기조건인원증서 명칭화면 구성
A참여일 30↑ 또는 활동 30건↑재집계 대기수 료 증배지 "맬리브레인 3기" · 헤딩 "수료를 축하드려요!" · 통계 2개(함께한 날 · 참여율) · 버튼 3개(수료증 저장하기 / 4기도 참여하기 → / 홈으로 돌아가기) · 폭죽 실행
B기록은 있으나 A 미달96 ~ 138명참 여 기 록배지 동일 · 헤딩 "이만큼 함께했어요!" · 통계 2개 · 버튼 3개(참여기록 저장하기 / …) · 폭죽 실행. 톤은 질책이 아니라 인정
C참여일 0 그리고 활동 0건14명 (1.9%)참 여 확 인배지 동일 · 헤딩 "4기에도 함께해요!" · 통계 없음(찍을 값이 없음) · 버튼 2개 · 저장 버튼 제외 · 폭죽 미실행
if   (참여일 >= 30) or (활동건수 >= 30) -> A
elif (참여일 >= 1)  or (활동건수 >= 1)  -> B
else                                    -> C
  • 위에서부터 먼저 맞는 것을 채택하며 원값으로 판정합니다. 참여율 반올림값을 쓰면 29.6일이 30%로 올라가 수료로 넘어갑니다.
  • 활동 건수는 판정에만 씁니다. 화면 어디에도 노출하지 않으며 payload에도 담지 않습니다. 사용자에게 보이는 숫자는 참여일과 참여율뿐입니다.
  • 분기는 서버 cert.tier를 그대로 신뢰합니다. 클라이언트에서 재판정하지 않습니다.
  • 배지 문구는 세 분기 모두 "맬리브레인 3기"로 같습니다. 축하 · 인사는 헤딩(S7-02)이 전담하며, 배지에서 반복하지 않습니다.
  • A · B 인원은 OR 기준 재집계 대기입니다. 기존 641 / 154 / 28은 참여일 단독 기준 값이라 쓸 수 없습니다. 확정된 것은 C = 14명(1.9%)뿐입니다. 탈퇴자는 발급 대상에서 제외하되 랭킹 모수(823명)에는 포함합니다.
