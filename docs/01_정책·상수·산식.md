## 2. 참여일 정의 (F-01)

아래 세 가지 중 **하나라도** 기록이 있는 날의 합집합. KST 자정 경계로 날짜를 계산하고, 같은 날 여러 건이 있어도 1일로 집계합니다. 사용자별로 다른 기준을 쓰지 않으며 전원 동일 규칙입니다.

1. 완료 활동 ≥ 1건 — `S1 outcome_raw · activity_date_kst`
2. 로그인 ≥ 1건 — `S8 login_history · is_success='Y'`
3. 걸음 > 0보 — `S7 step_count · stat_date`

```
참여일 = COUNT(DISTINCT (S1.activity_date_kst ∪ S8.login_date_kst ∪ S7.stat_date))
WHERE 날짜 BETWEEN 2026-03-03 AND 2026-10-30 (KST)
```

초안은 걸음 ∪ 로그인 2항이었습니다. **완료 활동을 3항으로 추가**한 이유는 걸음 미연동자(3.3%)가 게임 · 마음 활동을 해도 참여일이 0으로 집계돼 구조적으로 불리했기 때문입니다. S7에는 0보 행이 생성되지 않으므로 "걸은 날 수 = 행 수"이며 0 제외 필터는 불필요합니다.

> 분모 242일이 "평일 수"가 아닌 이유 — 프로그램은 평일 편성이지만 분모는 평일만 센 값이 아닙니다. 마지막 프로그램일이 10/30(금)이라 종료일을 거기에 맞췄고, 3/3부터 10/30까지의 **달력 일수**가 242일입니다. 참여일 쪽도 주말 로그인 · 걸음을 그대로 세므로 분자와 분모의 기준이 서로 맞습니다. 평일만 세는 곳은 요일별 참여율(F-07) 하나뿐이고, 거기서도 분모는 "기간 내 그 요일이 실제로 몇 번 있었는가"입니다.

## 4. 환산 매핑 테이블 (F-12 · F-13) — 13단계

거리와 칼로리는 숫자만으로는 와닿지 않아 아는 크기로 바꿔 보여줍니다. **두 표 모두 서버 설정값**으로 두어 4기에 갈아끼울 수 있게 합니다. 8단계에서 13단계로 늘린 판이며, 500kcal 이상 구간과 100~400km 사이 도시를 채웠습니다.

### 4-3. 선택 규칙

- **거리** — 총 거리 **이하인 지점 중 가장 먼 곳**을 고르고 `N = FLOOR(총거리 ÷ 편도)`를 계산합니다. N에 따라 문구가 달라집니다.
  - N = 1 → "…까지 **걸었어요**" (회차를 쓰지 않습니다. "부산까지 1회 걸었어요" 금지)
  - N = 2 → "…까지 **왕복했어요**"
  - N ≥ 3 → "…까지 **N회 걸었어요**"
  - 예: 714,200보 → 464km → 420km 이하 최대인 부산 → N=1 → "서울에서 부산까지 걸었어요"
- **칼로리** — 구간 경계는 인접 두 기준값의 **중간점**입니다. "사과 반 개" 같은 분수 표기가 나오지 않도록 항상 1개 단위로 떨어지게 잘랐습니다. 예: 3,607보 → 약 144kcal → 초코파이 하나 구간(138–185).
- 기준값은 대표 열량이므로 **"{음식}만큼"은 근사 표현**입니다. 정확한 열량을 주장하는 문구로 바꾸면 안 됩니다.
- 총 걸음이 7km(약 10,770보)에 못 미치면 첫 구간에도 들지 못합니다. 이 경우 **거리 환산 카드를 감춥니다** (P17과 동일 처리).

## 5. 수료 분기 A / B / C

SC-RP-07의 **문구 · 버튼 구성만** 분기됩니다. SC-RP-01 ~ 06의 레이아웃은 분기와 무관하게 동일하며, 값이 없는 항목만 개별 P코드 규칙을 따릅니다. 즉 "미참여자용 별도 화면"을 만들지 않습니다 — 화면 구조는 하나이고 값만 달라집니다.

| 분기 | 조건 | 인원 | 증서 명칭 | 화면 구성 |
|---|---|---|---|---|
| A | 참여일 30↑ **또는** 활동 30건↑ | 재집계 대기 | 수 료 증 | 배지 "맬리브레인 3기" · 헤딩 "수료를 축하드려요!" · 통계 2개(함께한 날 · 참여율) · 버튼 3개(수료증 저장하기 / 4기도 참여하기 → / 홈으로 돌아가기) · 폭죽 실행 |
| B | 기록은 있으나 A 미달 | 96 ~ 138명 | 참 여 기 록 | 배지 동일 · 헤딩 "이만큼 함께했어요!" · 통계 2개 · 버튼 3개(참여기록 저장하기 / …) · 폭죽 실행. 톤은 질책이 아니라 인정 |
| C | 참여일 0 **그리고** 활동 0건 | 14명 (1.9%) | 참 여 확 인 | 배지 동일 · 헤딩 "4기에도 함께해요!" · **통계 없음**(찍을 값이 없음) · 버튼 2개 · **저장 버튼 제외** · **폭죽 미실행** |

```
if   (참여일 >= 30) or (활동건수 >= 30) -> A
elif (참여일 >= 1)  or (활동건수 >= 1)  -> B
else                                    -> C
```

- **위에서부터 먼저 맞는 것**을 채택하며 **원값**으로 판정합니다. 참여율 반올림값을 쓰면 29.6일이 30%로 올라가 수료로 넘어갑니다.
- **활동 건수는 판정에만 씁니다.** 화면 어디에도 노출하지 않으며 payload에도 담지 않습니다. 사용자에게 보이는 숫자는 참여일과 참여율뿐입니다.
- **분기는 서버 `cert.tier`를 그대로 신뢰**합니다. 클라이언트에서 재판정하지 않습니다.
- 배지 문구는 세 분기 **모두 "맬리브레인 3기"**로 같습니다. 축하 · 인사는 헤딩(S7-02)이 전담하며, 배지에서 반복하지 않습니다.
- A · B 인원은 OR 기준 재집계 대기입니다. 기존 641 / 154 / 28은 참여일 단독 기준 값이라 쓸 수 없습니다. 확정된 것은 C = 14명(1.9%)뿐입니다. 탈퇴자는 발급 대상에서 제외하되 랭킹 모수(823명)에는 포함합니다.

> 수료증에 참여율을 함께 찍는 근거 — "함께한 날 142일 /242일 · 참여율 59%" 형태로 분모를 함께 노출합니다. 분모가 보이면 낮은 퍼센트도 "242일 중 30일"이라는 맥락에서 읽히고, 무엇보다 4기 참여 동기가 됩니다. 분모는 볼드 없이 연회색(#9AA3AD)으로 눌러 시각적 위계를 만듭니다.

## 6. 마음 안내박스 문구 (S5-08) — 4쌍

**종료 점수가 속한 구간 하나만** 보고 고릅니다. 시작 점수와의 변화 방향은 문구에 반영하지 않습니다 — 변화는 게이지의 실선 바늘과 점선 고스트가 이미 보여주고 있고, 문구까지 갈라놓으면 케이스가 9개를 넘습니다. 측정이 1회뿐인 경우(P04)도 그 값의 구간으로 고르며 전용 문구를 두지 않습니다.

|---|---|---|---|
| 양호 | 0~4 | 마음이 편안한 상태예요 | 기록을 남기는 것만으로도 마음은 정리됩니다.<br>4기에도 하루 한 줄씩 함께해요. |

## 7. 게이지 각도 산식 (S5-04 · S5-05) — 180° 반원

**2026-09-02 확정. 종전 "145° → 20° · 125° 스윕"을 대체합니다.**

```
각도(deg) = 180 − 점수 × 12        // 0점 → 180°(좌) · 15점 → 0°(우)
중심 (150, 150) · 아크 반지름 100 · 스트로크 18 · 바늘 길이 82
구간 경계 : 4.5점 = 126°  ·  9.5점 = 66°   (각 4° 간격의 정중앙)
```

| 아크 | 색 | 경로 | 각도 범위 |
|---|---|---|---|
| 양호 | #13BD7E | `M 50 150 A 100 100 0 0 1 88.4 71.2` | 180° → 128° |
| 주의 | #C9CFD6 | `M 94.1 67.1 A 100 100 0 0 1 187.5 57.3` | 124° → 68° |
| 위험 | #E1E5EA | `M 193.8 60.1 A 100 100 0 0 1 250 150` | 64° → 0° |

- 라벨은 양호(50, 176) · 주의(150, 30) · 위험(250, 176), 15px / 700.
- **실선 바늘 = 종료 점수**, **점선 고스트 = 시작 점수**(`stroke-opacity .5`). 둘 다 같은 원점에서 뻗고 축(허브)은 항상 노출합니다.
- 시작 = 종료이거나 측정이 1회면 **고스트를 그리지 않습니다** — 같은 각도를 두 번 그리면 값을 오독합니다.
- 구간 경계는 K-12를 읽어 그리고 하드코딩하지 않습니다.

## 8. 문구 · 표기 정책

- **대시 문자** — 집계 불가(P03)는 en dash `–`(U+2013)를 단위와 붙여 씁니다. `"–점"`. 하이픈(-)이나 공백 삽입("– 점") 금지.
- **범위 기호** — 게이지 구간 표기(S5-07)는 물결 `~`로 통일합니다. `양호 0~4 · 주의 5~9 · 위험 10~15`.
- **천 단위 콤마** — 모든 4자리 이상 숫자에 적용 (`714,200보` · `1,024,300보` · `862회`).
- **자리표시 문구** — 리스트에서 값이 모자란 행은 **"게임 기록이 없어요"**(#9AA3AD). "아직 여기까지예요"는 폐기했습니다.
- **음식명 강조** — 칼로리 헤드라인(S6-11)은 **음식명만 ExtraBold**이고 앞뒤 "매일" · "만큼 칼로리를 태웠어요"는 Regular입니다. 색은 전부 #191F28 — **굵기로만 강조하고 색은 바꾸지 않습니다**.
- **게임명** — 노션의 정식 명칭 그대로. 축약 금지("재밌는 숫자 퍼즐 9X9" → "숫자퍼즐" 불가).
- **기관명** — "인천남동구 보건소" 표기 그대로 (K-09).
- **4기 프로그램명** — K-13 하나로 통일. 바텀시트와 SC-RP-08이 서로 다른 명칭을 쓰지 않습니다.
- **표기명 우선순위 (P12)** — **닉네임 → 이름 → "회원님"** 순 (2026-09-07 확정). 둘 다 없으면 "회원님"(마스킹 미적용 · "님" 중복 금지).
- **이름 마스킹 (P12)** — 첫 글자와 끝 글자만 남기고 가운데를 전부 `*`. 3자 김맬리 → 김*리, 4자 남궁민수 → 남**수, 2자 김맬 → 김*, 1자 그대로. 글자 수는 공백 포함 문자 수로 세고 문자 종류와 무관하게 같은 규칙. 커버 · 랭킹(타인 포함) · 전 화면에 적용.
- **증서만 예외 — 마스킹하지 않습니다** (2026-09-07 확정). S7-06 표기명은 원문 그대로 찍습니다. 따라서 payload에 `user.cert_name`(원문)을 별도로 담고, 그 외 화면은 `user.masked_name`을 씁니다.
