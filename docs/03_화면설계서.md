## 2. 공통 레이아웃 · 안전 영역

기준 단말은 **안드로이드**입니다. 아트보드는 375 × 812이며 전 화면 같은 높이입니다. 화면마다 콘텐츠 양이 달라도 상단 배지와 하단 스크롤 힌트는 항상 같은 자리에 찍혀야 합니다.

### 2열 타일 폭 배분

| 화면 | 배분 | 간격 | 근거 |
|---|---|---|---|
| SC-RP-02 · 03 · 04 | 반반 | 12 | 값 길이가 비슷 |

| SC-RP-06 | **180 : 140** | 15 | 7자리 총 걸음(1,024,300보 · 137px)이 단위를 덮지 않게. 걸은 날은 3자리라 140으로 충분 |

### 값 크기 규칙

- 기본 타일 값은 **33px / 800 · 자간 −3.5%**, 단위는 15px / 600.
- **행 단위로 통일합니다** — 나란한 두 타일 중 한쪽이 폭 때문에 줄면 나머지도 같이 줄입니다.
- SC-RP-03(요일 · 시간)과 SC-RP-06(총 걸음 · 걸은 날 · 하루 평균)은 값이 구(句)이거나 자릿수가 커서 **26px**로 통일했습니다.
- **값 + 단위는 가로 오토레이아웃**(간격 2~3)으로 묶습니다. 단위를 고정 좌표에 두면 자릿수가 늘 때 값이 단위를 덮습니다.

### 구현 방식 — 오토레이아웃 + 절대 배치 2종

화면 프레임은 **세로 오토레이아웃**(패딩 64 / 20 / 40, 간격 12)이고 카드는 전부 폭을 채웁니다. 헤딩까지의 18px는 헤더 컨테이너의 하단 패딩 6px로 만듭니다 — 오토레이아웃은 간격을 하나만 가지므로 예외 간격은 패딩으로 흡수합니다.

닫기 버튼과 스크롤 힌트는 흐름에서 빼 **절대 배치**합니다. 다만 아트보드에서 같아 보이는 이 둘은 구현에서 성격이 다릅니다.

- **닫기(X)** — 오버레이 **뷰포트 기준 fixed**. 전 구간에 **인스턴스 하나**. 아트보드의 X 8개는 같은 버튼 하나를 8번 그린 것입니다. 섹션 내부 absolute로 구현하면 커버에서 스크롤하는 순간 화면 밖으로 밀려나 **오버레이를 닫을 수단이 사라집니다**.
- **스크롤 힌트** — 섹션마다 하나씩 있어 스크롤과 함께 지나갑니다. 8개 힌트는 서로 다른 8개 요소입니다.

> ! **812를 넘기면 화면을 나눕니다.** 콘텐츠가 한 화면을 넘으면 카드를 줄이는 대신 화면을 분리합니다. 이 원칙으로 SC-RP-04가 04와 04B로 갈라졌고, 05 · 06은 중복 요소를 덜어 한 장에 맞췄습니다. 812는 타협 대상이 아닙니다.

## 12. 모션 · 인터랙션

### 가장 중요한 구현 제약 — 스크롤 리빌은 progressive enhancement로

**기본 상태가 완성된 리포트**여야 합니다. 전 섹션이 보이고 카운터는 최종값입니다. IntersectionObserver가 실제로 콜백을 한 번 준 뒤에야 스크롤 리빌 모드로 강등하고, 그때부터 순차 등장이 동작합니다.

> ! IO가 발화하지 않는 환경(오프스크린 합성, PNG · PDF 캡처, 일부 웹뷰)에서 리빌을 게이트로 두면 **페이지 전체가 빈 화면으로 캡처**됩니다. 수료증 1:1 이미지 저장이 이 경로를 타므로 치명적입니다.
> 구현 — 초기 state = {전 섹션 visible, 카운터 최종값} → IO 첫 콜백에서 1회만 강등 → 이후 스크롤에 따라 순차 리빌. `prefers-reduced-motion` · IO 미지원 · 섹션 쿼리 실패 시에는 강등하지 않고 완성본을 유지합니다.

### 이징 커브 (임의 베지어 금지)

| 용도 | 값 |
|---|---|
| 진입 · 퇴장 · 데이터 리빌 | `cubic-bezier(.23, 1, .32, 1)` |
| 화면 내 이동 · 모핑 | `cubic-bezier(.77, 0, .175, 1)` |
| 증서 낙하 (드로어 성격) | `cubic-bezier(.3, 1, .4, 1)` |
| 폭죽 낙하 (중력 가속) | `cubic-bezier(.3, .5, .6, 1)` |

### 성능 함정

- **카운터 동시 실행 금지** — 여러 카운터를 각자 rAF 루프로 돌리면 프레임당 N회 리렌더가 발생하고 `backdrop-filter` 표면 약 50개와 겹쳐 메인 스레드가 잠깁니다. 카운터는 **단일 rAF 루프**에서 모든 값을 갱신하고 한 번의 커밋으로 반영합니다.
- **폭죽 조각 배열은 최초 1회만 생성해 캐시**합니다. 매 렌더 재생성 시 같은 원인으로 라이브락이 발생합니다.
- 카운트업은 **목표값이 0이면 생략**합니다 (P02).

### reduced motion — 0으로 죽이지 않습니다

`prefers-reduced-motion` 시 **transform만 제거하고 opacity 페이드는 남깁니다**. 전부 끄면 요소가 툭 나타나 오히려 인지 부하가 커집니다.

- `animation:none` · `transform:none` · `transition-property:opacity` · duration .2s · delay 0
- 금지 — `transition:all` / `scale(0)` 진입(→ `scale(.94)` + opacity) / UI에 `ease-in`

## 14. 화면별 검수 체크리스트

구현이 끝난 뒤 화면마다 확인할 항목입니다. 전부 "틀린 적이 있거나 틀리기 쉬운 것"만 골랐습니다.

**SC-RP-01 커버**
- ☐ 참여일 0일 계정에서 "242일 중 0일"이 그대로 나오는가
- ☐ 커버에서 07까지 스크롤하는 동안 **X 버튼이 계속 우상단에 떠 있는가** (섹션마다 새로 그려지지 않는가)
- ☐ 이름 미설정 계정에서 "회원님,"이 나오는가 ("회원님 님" 아님)
- ☐ 응답 payload에 원문 이름이 없는가
- ☐ 배지와 헤딩이 가운데 정렬인가 (02~06은 좌측 정렬)

**SC-RP-02 숫자 요약**
- ☐ 뇌 점수가 F-08로 나올 수 있는 14개 값 중 하나인가 (68 · 76은 불가)
- ☐ 측정 1회 계정에서 없는 쪽이 "–점"으로 나오는가 (감추지 않았는가)
- ☐ 꺾은선이 카드 **좌우 끝까지** 이어지는가
- ☐ 마음 기록 단위가 "일"인가 ("회" 아님)
- ☐ 참여일 0 계정에서 카운트업이 생략되는가

**SC-RP-03 집중 리듬**
- ☐ 요일 발생 횟수가 요일마다 다른 값으로 계산되는가
- ☐ 0% 요일에 트랙과 "0%"가 보이는가
- ☐ **동률이면 타일이 "골고루"이고 동률 막대가 모두 강조되는가**
- ☐ 시간 동점에서 이른 시간이 뽑히는가
- ☐ 0시와 12시의 오전 / 오후 변환이 맞는가
- ☐ 토 · 일이 어디에도 나타나지 않는가

**SC-RP-04 게임 하이라이트**
- ☐ 화면 어디에도 점수가 없는가
- ☐ 게임명이 축약되지 않았는가
- ☐ **S4-03 다크 카드 게임명 = TOP 3 1위 게임명 = S4-04 타일이 세는 게임**인가
- ☐ S4-04 횟수가 SC-RP-02 게임 횟수와 다른 값인가 (게임 하나 vs 전 게임 합)
- ☐ 1–2종 계정에서 TOP 3가 3행을 유지하고 빈 행이 "게임 기록이 없어요"인가
- ☐ 0종 계정에서 섹션이 사라지지 않는가

**SC-RP-04B 활동 점수 랭킹**
- ☐ 랭킹이 게임 점수가 아닌 **활동 점수** 기준인가
- ☐ 타일(S4B-04)과 배지(S4B-06)의 상위 %가 같은 값인가
- ☐ 두 타일의 가로 폭이 정확히 같은가 (160 / 160)
- ☐ 1–3위 이름이 마스킹돼 있는가 (블러를 해제해도 실명이 안 보이는가)
- ☐ **내 순위가 1–3위일 때 내 행만 선명하고 나머지 두 행은 블러가 남는가**
- ☐ 최하위 계정에서 "아래로 N명" 문구가 사라지는가
- ☐ 구분선에 구간 문구가 없는가

**SC-RP-05 마음 기록**
- ☐ 시작 · 종료 점수의 위계가 크기가 아닌 투명도로 만들어졌는가
- ☐ **게이지가 정확히 180° 반원인가** (좌 끝 = 0점, 우 끝 = 15점)
- ☐ 바늘이 가리키는 구간과 종료 점수의 K-12 구간이 일치하는가
- ☐ 구간 숫자가 설정값에서 오는가 (하드코딩 아님)
- ☐ 상태 텍스트가 양호 / 주의 / 위험 중 하나이고 **양호일 때만 녹색**인가
- ☐ 측정 1회 · 변화 없음 계정에서 고스트가 안 보이는가
- ☐ 고스트가 실선보다 옅게 보이는가 (`stroke-opacity`)

**SC-RP-06 걸음수 · 운동**
- ☐ 걸은 날 0일 계정에서 0으로 나누기가 안 나는가
- ☐ 하루 평균의 분모가 걸은 날 수인가 (참여일 아님)
- ☐ 1만보 초과 계정에서 **중앙 숫자가 실제값(124%)이고 아크만 100%에서 멈추는가**
- ☐ **미연동 계정에서 섹션 전체가 사라지고 리포트가 7개 섹션이 되는가**
- ☐ 총 걸음 0 계정에서 거리 · 칼로리 카드만 사라지는가
- ☐ 7자리 총 걸음(1,024,300보)에서 단위 "보"가 안 잘리는가
- ☐ 거리 헤드라인의 도착지와 각주의 편도 km가 같은 랜드마크인가
- ☐ N=1일 때 "1회"가 붙지 않는가
- ☐ 음식 아이콘이 헤드라인과 같은 가로선상에 있는가

**SC-RP-07 수료증**
- ☐ 참여일 29일 + 활동 30건 계정이 A로 판정되는가
- ☐ 참여일 0일 + 활동 0건 계정만 C로 가는가
- ☐ 판정에 참여율 반올림값이 쓰이지 않는가 · 클라이언트가 재판정하지 않는가
- ☐ 화면 어디에도 활동 건수가 안 보이는가
- ☐ 배지가 세 분기 모두 "맬리브레인 3기"인가
- ☐ 증서 캡처 결과가 정확히 정사각형이고 실명이 없는가
- ☐ 인장이 발급 정보에 겹쳐 있고 multiply로 합성되는가
- ☐ C 계정에서 저장 버튼과 폭죽이 모두 없는가
- ☐ 07-h 바텀시트가 **화면 폭에 맞춰** 뜨는가 (뷰포트 중앙이 아님)

**SC-RP-08 4기 신청**
- ☐ 완료 · 실패의 배지 · 헤딩 · 아이콘 · 본문 · 버튼이 모두 함께 바뀌는가
- ☐ 프로그램 명칭이 07-h 시트와 정확히 같은가 (K-13)
- ☐ 신청 완료 후 리포트로 돌아가면 S7-11이 비활성 + 문구 변경 상태인가
- ☐ 이미 신청한 계정이 시트를 건너뛰고 완료 화면으로 가는가
