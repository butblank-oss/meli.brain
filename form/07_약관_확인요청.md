# 0. 먼저 정해야 답이 갈리는 것

## Q0. 이 사업에서 **개인정보 처리자가 누구**입니까?

이것에 따라 동의서의 명의·구조·보유기간이 전부 달라집니다. **가장 먼저 답이 필요합니다.**

| | (가) 원메딕스가 처리자 | (나) 남동구 보건소가 처리자 |
|---|---|---|
| 구조 | 원메딕스가 수집 → 보건소에 **제3자 제공** | 보건소가 수집 → 원메딕스는 **수탁자** |
| 동의 명의 | 원메딕스 (맬리브레인) | 인천 남동구 보건소 |
| 필요한 동의 | 이용약관 + 개인정보 수집·이용 + **제3자 제공** | 보건소 수집·이용 동의 (제3자 제공 불필요) |
| 보유기간 기준 | 회원 탈퇴 시까지 (맬리 기준) | 지자체 기록물 보존 기준 |
| 처리방침 개정 | 원메딕스 처리방침에 보건소 제공 명시 | 보건소 개인정보파일 등록 필요 |
| 현재 초안 | **이 구조로 작성돼 있음** | — |

**판단 근거로 필요한 것**: 남동구 보건소와 맺은 **계약 형태** (용역계약 / 위탁계약 / 민간 자체사업 + 협약).
계약서에 "개인정보 처리 위탁" 조항이 있으면 (나)일 가능성이 높습니다.

> 실무에서는 **(다) 혼합형**도 흔합니다 — 맬리 회원가입은 원메딕스가 처리자,
> 치매예방교실 참여 정보만 보건소에 제공. 현재 초안이 이 구조에 가장 가깝습니다.
> 다만 **보건소 담당자가 직접 승인하는 구조**(2026-09-21 변경)라면 (나)에 훨씬 가까워집니다. 판단 근거가 바뀌었습니다.

# C. 기존 문서와 어긋나 개정이 필요한 것 (8) ★

여기가 핵심입니다. **지금 문서 그대로는 신청폼을 못 엽니다.**

## C-01. 거주 행정동이 수집 항목에 없음 <span>필수</span>

| | |
|---|---|
| 현행 | 처리방침 제3조 필수항목 = **이름, 생년, 성별, 휴대전화번호** |
| 신청폼 | 이름, 휴대전화번호, **거주 행정동** |
| 문제 | 거주 행정동이 처리방침 어디에도 없습니다. **고지 없이 수집**하는 상태가 됩니다 |
| 조치 | 처리방침 제3조에 `거주 행정동(시·군·구·읍면동)` 추가. 수집 목적에 "관내 거주 확인" 명시 |

## C-02. 생년 · 성별을 신청폼에서 받지 않음 <span>필수</span>

| | |
|---|---|
| 현행 | 처리방침 제3조 **필수항목**에 생년·성별이 있음 |
| 신청폼 | 받지 않음. 그런데 **회원 생성까지** 일어남 |
| 문제 | 필수항목 없이 회원이 만들어져 처리방침과 실제가 어긋납니다 |
| 조치 | 둘 중 하나 — **(가)** 신청폼에 생년·성별 추가 (시니어 입력 부담 증가, 권장하지 않음) / **(나)** 처리방침을 "가입 경로별 수집 항목"으로 분리 기재 **(권장)** |

> 참고: 제3조 2항 **선택항목**에 이름·성별·생년월일이 중복으로 들어가 있습니다.
> 필수항목과 겹쳐서 어느 쪽이 맞는지 불명확합니다. 이 기회에 정리가 필요합니다.

## C-03. 제3자 제공에 남동구 보건소가 없음 <span>필수</span>

| | |
|---|---|
| 현행 | 처리방침 제4조는 **원칙만** 기술. 제공받는 자 목록이 없음 |
| 신청폼 | 보건소에 이름·전화번호·거주동·출석·수료 여부를 제공 |
| 문제 | 개인정보보호법 §17②는 **제공받는 자 · 목적 · 항목 · 보유기간 · 거부권과 불이익**을 모두 알리도록 요구합니다 |
| 조치 | 처리방침 제4조에 제3자 제공 표 신설. `terms.html`의 필수 3번 항목이 그 내용입니다 |

> 제25조(통계분석 자료의 가공과 제공)의 "요양기관 · 공공기관 제공"은 **비식별 통계**라 이것과 별개입니다.
> 실명 정보 제공 근거로 쓸 수 없습니다.
