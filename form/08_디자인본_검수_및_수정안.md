## 1. 되돌려야 하는 것 — 정책 회귀 3건 ★

### R-01 기존 회원의 이름·거주지가 문자 확인 없이 화면에 뜬다 <span>치명</span>

재현했습니다. 어르신 모드에서 **아무 번호나 11자리**를 넣으면 곧바로 이렇게 됩니다.

```
010-1234-5678
✓ 이미 맬리브레인을 쓰고 계신 김순자 님이시네요. 적어두신 내용을 채워뒀어요.
이름   [ 김순자 ]
사시는 곳  인천 남동구 구월1동
아직 남은 것: 동의        ← 동의만 누르면 제출됨
```

QR은 현장 밖에서도 열립니다. 남의 번호를 넣으면 **그 사람의 이름과 거주 동이 노출**되고,
그대로 제출하면 **남의 계정에 내 신청이 붙습니다.**

이건 제가 v0.1 감사에서 `A-01` 치명으로 잡았고, 확인 과정에서 **"기존회원일 때만 SMS"** 를 직접 고르신 항목입니다.
디자인 버전은 문자 확인을 **직원 모드에서만** 걸고 어르신 모드(= 유입 85%)에서는 뺐습니다.

| | 디자인본 | 수정 후 |
|---|---|---|
| 신규 번호 · 어르신 | 인증 없음 | 인증 없음 (유지) |
| **기존 회원 · 어르신** | **인증 없이 이름·동 자동 채움** | **인증 통과 후에만 채움** |
| 신규 번호 · 직원 | 인증 | 인증 (유지) |
| 기존 회원 · 직원 | 인증 | 인증 (유지) |

**조치** — `checkPhone()`의 `member` 분기에서 자동 채움을 걷어내고 모드와 무관하게 인증을 띄웁니다.
채우는 시점을 `verifyOtp()` 성공 이후로 옮겼습니다. 잠금 장치(`otpShown && !otpVerified` → 이름·동 비활성)는
디자인본에 **이미 구현돼 있었습니다.** 호출만 안 하고 있었던 것이라 수정이 작습니다.

### R-02 3기 참여자도 같은 경로로 뚫린다 <span>치명</span>

`confirmPrev()`가 팝업에서 [이어서 신청]을 누르면 어르신 모드에서 인증 없이 이름을 채웁니다.
3기 참여자 명단은 보건소가 보유한 실명 명단이라 R-01보다 노출 범위가 좁지 않습니다.

**조치** — R-01과 동일. 팝업 확인 후 인증을 띄우고, 통과해야 채웁니다.
팝업 자체(3기 참여자에게 먼저 알리는 것)는 좋은 설계라 그대로 뒀습니다.

### R-03 인증 실패 횟수 제한이 없다 <span>중대</span>

디자인본은 `"불일치는 [확인] 누른 시점에만 판정하고 몇 번째인지 표시. **잠금 없음**"` 입니다.
6자리는 100만 가지뿐이라 시도 제한이 없으면 인증이 형식적인 절차가 됩니다.
직원 모드의 인증은 **번호 오타 검증**이 주목적이지만, R-01을 되살리면 **본인 확인** 역할도 겸하게 되므로 제한이 필요합니다.

**조치** — 5회 실패 시 10분 잠금. 확인·재발송 버튼을 함께 잠그고 보건소 문의로 연결합니다.
`(3/5번째)`로 남은 횟수를 보여줍니다.

> **서버가 정본입니다.** 클라이언트 카운트는 안내용이고, 시도 횟수·잠금은 서버에서 세야 합니다
> (`ia.html` §9 서버 요구사항 3번).

## 2. 확대 시 버그 1건

### R-04 글자를 키우면 "아래에 더 있어요 ▾" 배지가 고정 바 뒤로 숨는다

배지가 `bottom:124px` 고정인데, 고정 제출 바는 글자 배율에 따라 **124 → 181px**까지 자랍니다.

| 글자 배율 | 고정 바 높이 | 배지 가려짐 (수정 전) | 수정 후 |
|---|---|---|---|
| 기본 (1) | 124px | 아니오 | 아니오 |
| 아주 크게 (1.3) | 176px | **예** | 아니오 |
| 최대 (1.6) | 181px | **예** | 아니오 |

폰 글자 크기를 이미 키워둔 분에게만 생기는 버그라, **정작 그 안내가 가장 필요한 사용자에게만 안 보입니다.**

**조치** — 고정 바의 실제 높이를 재서 `--ctah`로 내리고 배지를 `bottom:var(--ctah)`로 바꿨습니다.
`ResizeObserver`로 글자 크기 변경에 따라갑니다. 원안(`index.html` v0.2)이 쓰던 방식입니다.

## 5. 수용한 개선 10건 — 원안보다 낫습니다

스펙에 역반영했습니다. 이건 **디자인본이 정본**입니다.

| # | 개선 | 왜 더 나은가 |
|---|---|---|
| I-01 | **직원 모드는 신규 번호도 문자 확인** | 원안은 기존 회원만 인증. 대리 접수는 번호 오타가 곧 로그인 불가라 신규도 검증하는 게 맞습니다 |
| I-02 | **3기 참여자 확인 팝업** (시트 3번째) | 자동 채움 전에 "3기에 참여하셨던 분이네요"로 한 번 확인. 본인 확인 단계가 하나 늘어 안전하고, 어르신에게는 안심 신호가 됩니다 |
| I-03 | **대상자 바** (직원 모드 sticky top) — "접수 중 · {번호}" + "오늘 N번째" | 직원이 지금 누구를 접수 중인지 화면에서 확인. 연속 접수에서 섞이는 사고를 막습니다 |
| I-04 | **제출 완료 시 직원 모드 자동 해제** | 원안은 모드 유지. 공용 기기가 직원 모드로 방치되는 `FP-03` 리스크를 없앱니다. 완료 화면의 [다음 분 신청받기]로 재진입 |
| I-05 | **상태색 4종** (오류·경고·성공 + **안내 i**) | 원안 3종. "확인하고 있어요" 같은 중립 상태를 성공(초록)으로 표시하던 문제 해결 |
| I-06 | **네이비 #1F3C5D / 직원 웜그레이 #3A342C** | 모드가 색으로 즉시 구분됩니다. 대비도 11.3:1 · 12.3:1로 충분 |
| I-07 | **보건소 번호를 `{전화번호}` 자리표시로 통일** | 주입 지점이 화면 7곳 + 약관 2곳으로 명확해졌습니다 |
| I-08 | **인증번호 입력에 `letter-spacing:.2em` + `tabular-nums`** | 6자리를 두 개씩 끊어 읽기 쉬워집니다 |
| I-09 | **재발송 쿨다운 중 밑줄·포인터 제거** | 누를 수 없다는 것이 형태로도 전달됩니다 |
| I-10 | **체크박스 이벤트 전파 버그를 README에 명시** | 행 전체 탭 + 체크박스 탭이 겹쳐 토글이 상쇄되던 실제 버그. 구현자가 반복하지 않도록 기록한 것이 좋습니다 |

## 8. 적용 방법

```
design_handoff_malibrain_apply_form_fixed/
  Malibrain Apply Form.dc.html   ← 12군데 수정
  IA 화면설계서.dc.html           (변경 없음)
  README.md                      (변경 없음 — 아래 4곳은 README도 고쳐야 함)
  doc-page.js · support.js       (변경 없음)
  spec/                          (변경 없음)
```

**README.md도 함께 고쳐야 하는 곳 4군데**

| 위치 | 현재 | 고칠 내용 |
|---|---|---|
| `조회 결과 분기` 표 · FE-05 | "이름·동 자동 채움, **인증 없음**, 동의만 받고 제출" | "**문자 확인 후** 이름·동 자동 채움. 인증 전에는 이름·동·동의 비활성" |
| `조회 결과 분기` 표 · FE-07 | "팝업으로 먼저 알림 → [이어서 신청]에서 이름 자동 채움" | "팝업 확인 → **문자 인증** → 통과 후 이름 자동 채움" |

| `SC-F-01` 컴포넌트 9 | "bottom 124px" | "고정 바 높이를 측정한 `--ctah`" |

**실제 구현으로 옮길 때 지켜야 할 것** (`ia.html` §9와 동일)
- 조회 API 응답에 **이름·거주 동을 포함하지 않습니다.** 화면을 잠가도 응답에 있으면 R-01은 그대로입니다
- 인증 시도 횟수·잠금·쿨다운은 **서버가 셉니다**
- 제출은 **멱등** 처리 — 같은 번호는 기존 건 반환
