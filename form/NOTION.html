승인 화면 규칙 (AD-R)

코드 규칙
AD-R-01 확인할 신청이 기본 화면이다. 통계나 대시보드를 먼저 보여주지 않는다
AD-R-02 반려에는 사유가 반드시 붙는다. 사유 없이 반려할 수 없다
AD-R-03 처리 전에 신청자에게 보일 문장을 보여준다. 분류만 고르고 끝내지 않는다
AD-R-04 모든 처리는 되돌릴 수 있다. 오터치는 반드시 생긴다
AD-R-05 상세 화면으로 들어가지 않는다. 판단에 필요한 정보를 목록 카드에 다 올린다
AD-R-06 의심 건은 붉은 줄로 먼저 알린다. 다만 자동으로 반려하지는 않는다
AD-R-07 처리자 · 시각 · 사유를 남긴다. 나중에 못 만든다
AD-R-08 문자 발송 실패가 상태 전이를 막지 않는다

상태 전이

폼 상태 (전화번호 조회 결과와 인증 여부가 결정)

IDLE → CHECKING → NEW / NEEDS_OTP / BLOCKED → (VERIFIED) → SUBMITTING

신청 건 상태 (제출 이후)

상태 진입 어르신이 보는 화면 앱에서 가능한 것
PENDING 제출 성공 SC-F-02 → 앱에서는 SC-A-02 설치 · 로그인 · 게임 · 걷기 (교실은 잠김)
APPROVED 관리자 [승인하기] SC-A-04 오늘의 프로그램 전부
REJECTED 관리자 [받지 않음] + 사유 SC-A-03 — 사유 그대로 노출 게임 · 걷기만

불변식 5가지

  1. 번호가 바뀌면 무조건 CHECKING 이전으로 돌아간다. 인증·자동채움은 남지 않는다
  2. NEEDS_OTP 계열에서는 이름·동 필드에 어떤 값도 채워 넣지 않는다
  3. SUBMITTING 중에는 어떤 입력도 받지 않고, 실패 시 입력값을 하나도 잃지 않는다
  4. PENDING에서도 앱 설치와 로그인은 막지 않는다. 교실 기능만 잠근다
  5. PENDING → APPROVED 전환으로 화면이 저절로 바뀌지 않는다. 사용자가 버튼을 눌러야 넘어간다

서버 요구사항 (12건)

코드 내용 없으면
C-1 조회 API 응답에 이름·거주 동을 포함하지 않는다 화면을 잠가도 응답에 있으면 그대로 보임 (가장 중요)
C-2 조회 API 레이트 리밋 (IP·번호 단위) 번호 대입으로 참여자 명단을 통째로 캐냄
C-3 인증번호 검증·시도 횟수·잠금·쿨다운을 전부 서버에서 클라이언트 조작으로 인증을 건너뜀
C-4 제출 시 거주 동 코드를 관내 화이트리스트로 재검증 관외 신청이 승인 목록에 올라옴
C-5 제출 멱등 처리 연타·재시도로 중복 접수
C-6 미로그인 30일 계정 자동 정리 타인 번호 계정이 실제 소유자 가입을 영구히 막음
C-7 동의 저장 시 항목별 동의·시각·약관 버전·작성 경로 기록 분쟁 시 동의 입증 불가
C-8 직원 대리 접수는 channel=staff_proxy 로 구분 저장 대리 작성 건을 사후에 가려낼 수 없음
C-9 인증 토큰 짧은 유효기간 + 제출 시 재검증 인증만 받아두고 나중에 다른 값으로 제출
C-10 완료 문자 발송을 제출 성공과 분리 문자 장애가 가입 전체를 막음
C-11 미로그인 계정 정리 집행 시작일을 2026-10-18 이후로 제9조 2항 5호는 새로 생긴 해지 사유 — 30일 공지 미확보
C-12 약관 개정 공지 + 개별 통지 + 발송 로그 보관 불리한 변경의 절차 증거가 남지 않음
