# 맬리브레인 신청폼 개선 — 프로토타입 v0.1

인천 남동구 보건소 치매예방교실 신청폼(`meli.health/invitations/dementia3/form`) 개선안.
2026-09-18 가입 절차 개선 회의 결정사항 반영.

- **프로토타입**: [`index.html`](index.html) — 왼쪽 검수 패널에서 상태 7종 / 글자 크기 3단계 전환
- **약관 검토용**: [`terms.html`](terms.html) — 필수 3 + 선택 1 전문

---

## 1. 무엇이 바뀌나

| | 현재 | 개선안 |
|---|---|---|
| 승인 | 직원이 어드민 PC에서 수동 승인 | **제출 즉시 자동 승인** (관내 동 선택이 관외 필터를 대신함) |
| 회원가입 | 신청폼 + 앱에서 또 가입 | **앱 가입 제거**, 신청폼이 회원까지 생성 → 앱은 전화번호 로그인만 |
| 완료 화면 | "곧 문자가 갑니다" 안내만 | **그 자리에서 설치**: 스토어 버튼 2개 + QR + 3단계 안내 |
| 주소 | 자유 텍스트 | **인천 남동구 고정 + 관내 20개 동 버튼 선택** |
| 동의 | 체크박스 1개, 전문 없음 | **필수 3 + 선택 1**, 각 항목 전문 시트 |
| 대리 작성 | 규정 없음 | **탭 분리 + SMS 인증 + 본인 직접 동의** |

## 2. 화면 구조

```
신청폼  [직접 신청] [도움받아 신청]     ← 탭 2개
  1 휴대전화 번호   (+ 확인/인증번호)
  2 인증번호 6자리  ← 도움받아 신청 탭에서만
  3 이름
  4 사시는 곳       인천 남동구(고정) + 동 선택 시트
  5 동의            필수3 + 선택1, 모두 동의 1개
  [신청하기]
        ↓
신청완료  승인 완료 + 신청내역 + 설치 3단계 + 스토어 2 + QR + 문자 안내 + 보건소 전화
```

### 탭 A — 직접 신청
전화번호 입력 → `확인` → 기존 회원이면 **마스킹된 이름(홍*동)** 으로 본인 확인 후 이름·동 자동 채움. 신규면 직접 입력.
현장에서 본인이 자기 폰으로 쓰므로 SMS 인증은 걸지 않음(회의 결론).

### 탭 B — 도움받아 신청 (보건소 직원)
직원이 대신 입력하되 **번호 오타 = 로그인 불가**라서 SMS 인증번호로 번호를 검증한다.
동의 4개는 어르신께 화면을 보여드리고 **본인이 직접 누르게** 하고, `작성경로=직원대리`·직원 식별자·동의 시각을 함께 저장한다.

## 3. 시니어 접근성 기준

- 본문 17px / 입력 19px / 터치 타겟 최소 56px, 동의 체크박스 32px + 44px 히트박스
- OS 폰트 200% 확대에서도 레이아웃 유지 (`--fs` 배율로 검증 가능)
- 한 화면 스크롤 1폼 — 단계 분할(멀티스텝) 안 함. 되돌아가기 부담이 더 큼
- 오류는 필드 **바로 아래** 빨간 글씨로. 상단 요약 에러 배너 안 씀
- 문구는 "~해 주세요" 존대 + 명사 나열 금지 ("동 선택" ✗ → "어느 동에 사세요?" ✓)
- 실패 시 항상 대안 제시: 인증 잠금 → "직접 신청 탭으로", 설치 실패 → 문자/보건소 전화

## 4. 보안 · 개인정보 처리

| 항목 | 처리 |
|---|---|
| 기존 회원 조회 | 이름을 `홍*동`으로 마스킹해 본인 확인만. 번호만 알면 타인 정보를 못 얻게 함 |
| SMS 인증번호 | 6자리 · 유효 5분 · 재발송 30초 쿨다운 · **5회 실패 시 10분 잠금** |
| 완료 화면 | 전화번호 뒷 4자리만 노출 (`010-****-1234`) — 현장 어깨너머 노출 방지 |
| 동의 분리 | 개인정보보호법 §22 ④ — 필수/선택 분리, 선택 미동의 시 불이익 없음 명시 |
| 대리 작성 | 동의 주체는 본인. 대리 입력 사실·직원 식별자·동의 시각 저장 |
| 관외 차단 | 자유 입력 제거, 관내 20개 행정동만 선택 가능 → 자동승인의 근거 |
| 크롤링 | 신청폼은 `noindex, nofollow` |

### 서버에서 반드시 막아야 할 것 (프로토타입에서는 미구현)
- 전화번호 조회 API **레이트 리밋** — 없으면 번호 대입으로 회원 여부를 캐낼 수 있음
- 인증번호 검증은 **서버에서만**. 재발송 쿨다운·시도 횟수도 서버 카운트
- 제출 시 동 코드를 서버에서 관내 코드 화이트리스트와 재검증
- 동일 번호 중복 제출은 신규 생성 대신 기존 건 반환 (완료 화면으로)

## 5. 상태 정의 (검수 패널 프리셋)

| 코드 | 상태 | 처리 |
|---|---|---|
| P-01 | 신규 신청자 | "처음 오셨네요" → 이름·동 직접 입력 |
| P-02 | 기존 맬리 회원 | 마스킹 이름 확인 → 이름·동 자동 채움 |
| P-03 | 이미 4기 신청함 | 중복 접수 안 함 → 완료 화면으로 보내 설치만 안내 |
| P-04 | 전화번호 형식 오류 | 필드 하단 오류, 확인 버튼 비활성 |
| P-05 | 인증번호 불일치 | 남은 횟수 표시 (n/5) |
| P-06 | 인증 5회 실패 | 10분 잠금 + 직접 신청 탭 우회 안내 |
| P-07 | 필수 동의 미체크 | 제출 버튼 비활성 + 어느 항목이 빠졌는지 안내 |

## 6. 남은 확인 사항

- [ ] **자동승인 가부** — "이 폼으로 신청한 분은 무조건 승인해도 되는지" 보건소 확인 (김소리)
- [ ] 남동구 행정동 20개 목록이 보건소 기준과 일치하는지 확인
- [ ] 보건소 대표 전화번호 (현재 `032-000-0000` 자리표시)
- [ ] 위탁사 실명 (문자 발송 / 클라우드) — 개인정보 동의서에 실명 필요
- [ ] 개인정보 보유기간 "사업 종료 후 1년"이 지자체 기록물 기준과 맞는지 법무 확인
- [ ] 앱 스토어 링크 · QR 실제 URL (현재 자리표시)
- [ ] 타 기관용 폼을 팔 때의 URL 규칙 (`/invitations/{기관}/{기수}/form`)

## 7. 타 기관 확장

기관마다 주소를 따로 따는 구조이므로 다음 값만 기관별 설정으로 분리하면 된다.

```
기관명, 기수명, 관내 행정동 목록, 보건소 전화번호,
제3자 제공 동의서의 제공받는 곳/목적/보유기간, 자동승인 여부
```

폼 구조·동의 항목 수·문구 톤은 공통으로 유지한다.
