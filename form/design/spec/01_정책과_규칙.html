01. 정책과 규칙

배경 — 왜 바꾸나

현장 QR로 모집하는데 신청폼과 앱 회원가입이 이중으로 돌고 있어서 온보딩이 끊깁니다. 신청폼만 내고 앱 가입을 안 한 사람은 관리자가 승인해 줄 수도 없습니다. 유입 비중은 신청폼 약 85%, 앱 직접 가입 약 5%라 신청폼 경로가 우선입니다.

확정된 결정 (2026-09-18 회의)

항목 결정
가입 게이트 신청폼 · 앱 직접 가입 두 경로 모두 유지
승인 방식 신청폼 경로는 자동 승인 / 앱 직접 가입은 관리자 승인
신청폼 경로 회원가입 앱 회원가입 단계 제거, 전화번호 로그인만으로 진입
개발 우선순위 신청폼 경로 우선
앱 가입 시 거주지역 선택 넣지 않음 (시니어에게 허들이 큼)
약관 · 동의 이용약관 · 개인정보처리방침 · 제3자 제공 동의 재제작

이 폼의 4가지 전제

  1. 자동 승인 — 남동구 보건소 전용 폼이므로 제출 즉시 승인 상태로 회원을 생성합니다. 관외 필터는 관리자 판단 대신 거주 동 선택이 대신합니다.
  2. 앱 회원가입 제거 — 신청폼이 회원까지 만들고, 앱에서는 전화번호 로그인만 합니다.
  3. 그 자리에서 설치 — 완료 화면이 "문자 기다리세요"로 끝나지 않고, 기기를 자동 판별한 설치 버튼 · QR · 3단계 안내를 바로 제공합니다.
  4. 어르신에게 선택지를 주지 않음 — 직원 대리 접수 모드는 탭으로 노출하지 않고 폼 맨 아래 작은 링크로만 진입합니다.

분기 규칙 16개 (IA-R)

코드 규칙 이유
IA-R-01 이 폼으로 들어온 신청은 제출 즉시 승인 완료로 저장한다 남동구 전용 폼이므로 관리자 판단이 필요 없다
IA-R-02 이 폼의 제출은 회원 생성까지 완료한다. 앱에서 다시 가입시키지 않는다 이중 게이트가 이탈의 실제 원인
IA-R-03 기존 회원으로 판정된 번호는 SMS 인증 통과 전까지 이름·동·동의 영역을 잠근다 번호만으로 타인 정보를 열람하는 경로 차단
IA-R-04 신규 번호는 SMS를 요구하지 않는다 노출할 기존 정보가 없다. 85% 경로의 단계를 늘리지 않는다
IA-R-05 거주지는 관내 20개 행정동 선택으로만 받는다. 자유 입력·검색 없음 자동 승인의 근거이자 시니어 입력 허들 제거
IA-R-06 동 시트에는 반드시 탈출구 2개를 둔다 막다른 길에서의 이탈은 복구가 안 된다
IA-R-07 동의는 필수 3개뿐이다. 선택 동의는 두지 않는다 필수만 받으면 §22 ④의 분리 표시 부담이 사라진다
IA-R-08 직원 대리 접수는 탭으로 노출하지 않는다. 폼 맨 아래 링크로만 진입한다 어르신에게 첫 화면의 선택지를 주지 않는다
IA-R-09 직원 모드에서는 임시저장을 하지 않고 기존 저장분도 지운다 공용 기기에 개인정보를 남기지 않는다
IA-R-10 모드를 바꾸면 번호 확인·인증을 처음부터 다시 밟는다 앞 모드의 확인이 뒤 모드의 인증을 대신하면 안 된다
IA-R-11 화면은 저절로 바뀌지 않는다. 이동은 항상 사용자가 버튼을 눌러서 한다 시니어는 자동 전환을 오작동으로 인식한다
IA-R-12 제출 버튼은 비활성화하지 않는다. 누르면 빠진 곳으로 데려간다 비활성 버튼은 스크린리더가 읽지 않고 아무 피드백도 주지 않는다
IA-R-13 전화번호를 고치면 그 뒤 단계(인증·자동채움)를 전부 무효화한다 인증한 번호와 제출되는 번호가 달라지는 것을 막는다
IA-R-14 완료·중복·관외 화면에는 항상 보건소 전화번호를 둔다 화면에서 못 푸는 문제의 최종 탈출구
IA-R-15 상태는 색으로만 전달하지 않는다. 아이콘·문구를 함께 쓴다 색각 이상·저조도 화면 대응
IA-R-16 기관별 설정값만 바꿔 타 기관 폼을 만든다. 구조·문구 톤은 공통 타 기관 확장

절대 하면 안 되는 것 12가지

리디자인 과정에서 흔히 깨지는 것들입니다.

  1. 제출 버튼을 문서 맨 아래에 두기 — 어르신은 스크롤 개념이 약해서 못 찾습니다. 붙박이(sticky)여야 합니다.
  2. 조상 요소에 overflow:hidden — position:sticky가 조용히 죽습니다. 시각적으로 티가 안 나서 놓치기 쉽습니다.
  3. 제출 버튼을 비활성화(disabled) — 스크린리더가 읽지 않고, 왜 못 누르는지 알 수 없습니다.
  4. 모든 글자를 같은 비율로 확대 — 헤더만 첫 화면을 다 먹고 첫 입력칸이 밀려납니다.
  5. 상태를 색으로만 구분 — 빨강/초록만으로는 색각 이상·실외 밝은 화면에서 구분되지 않습니다.
  6. 미체크 체크박스에 회색 체크 표시 — 이미 체크된 것으로 보입니다. 빈 네모여야 합니다.
  7. 화면을 자동으로 전환 — 어르신은 자기가 잘못 눌렀다고 생각합니다.
  8. 오류를 화면 상단에 요약 배너로 — 스크롤을 요구합니다. 오류는 해당 필드 바로 아래에.
  9. 입력 중에 글자를 지우거나 막기 — 자판 고장으로 인식합니다. 검증은 제출 시점에.
  10. 필수 표시를 * 별표로 — 의미가 전달되지 않습니다. 글자 배지로.
  11. 색으로 지칭하는 문구 — "파란 버튼을 누르세요" ✗ → "설치 버튼을 누르세요" ✓
  12. 단계를 여러 화면으로 쪼개기 — 되돌아가기가 어렵고 현재 위치를 계속 추적해야 합니다.

남긴 리스크 3가지 (알고 둔 것)

  1. 신규 가입은 무인증 — 타인 번호로 신규 접수가 가능합니다. 다만 실제 소유자가 아니면 앱 로그인이 안 되므로 피해는 "그 번호로 가입이 막힘"에 그칩니다. 서버에서 미로그인 30일 계정 자동 정리가 필요합니다.
  2. 거주 동은 자기 신고 — 거짓 선택을 화면에서 막을 수 없습니다. 보건소 현장 확인이 최종 게이트입니다.
  3. 임시저장이 브라우저에 남음 — 어르신 본인 기기라는 전제입니다. 직원 모드에서는 저장하지 않습니다.
