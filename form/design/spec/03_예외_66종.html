03. 예외 66종

화면이 가져야 하는 모든 상태입니다. 새 상태를 만들거나 기존 상태를 합치지 마세요. 구현 = 프로토타입에서 재현 가능 / 서버 = 서버가 판정 / 미정 = 값·정책 미확정

FE — 전화번호 조회 (11)

코드 상황 화면 처리
FE-01 구현 11자리를 채웠는데 형식이 틀림 입력칸 빨강 + 안내. 11자리 전에는 아무 오류도 띄우지 않음 — 타이핑 중 빨간 글씨는 어르신을 멈추게 함
FE-02 구현 번호를 비운 채 제출 전화번호 칸으로 스크롤·포커스 + 안내
FE-03 구현 조회 API 실패 "어르신 잘못이 아닙니다" + 다시 해보기. 3회 실패 시 보건소 전화 노출
FE-04 구현 조회 결과 = 신규 "처음 오셨네요" — 남은 일이 2개뿐임을 알려 부담을 줄임
FE-05 구현 서버 조회 결과 = 기존 회원 이름·동·동의 영역을 잠그고 SMS 인증 블록을 엶. 인증 전에는 기존 정보를 한 글자도 안 보냄. 모드와 무관하게 적용 — 어르신 모드에서도 예외 없음
FE-06 구현 서버 이번 기수에 이미 신청함 안내 + 신청한 내용 보기 버튼. 자동 전환 금지
FE-07 구현 서버 이전 기수(3기) 참여자 먼저 팝업(SH-03)으로 알림 → [이어서 신청] → SMS 인증 → 통과 후 이름·동 채움. 기존 계정에 4기를 붙임
FE-08 서버 이용 제한 계정 사유를 화면에 밝히지 않음 (제한 규칙 노출 시 우회 시도). 보건소 전화로 연결
FE-09 구현 조회·인증 후 번호를 고침 인증·자동채움·인증 블록을 전부 초기화. 소리 없이 처리
FE-10 서버 조회 과다 시도 "1분 뒤에 다시" — 번호 대입으로 회원 여부를 캐내는 것을 막음
FE-11 미정 번호 재사용 — 전 소유자 계정 인증 후 자동채움된 이름을 수정 가능하게 둔 것이 1차 대응

FA — SMS 인증 (10)

코드 상황 화면 처리
FA-00 구현 인증을 요구하는 경우 ① 기존 회원·이전 기수 (모드 무관) ② 직원 대리 접수는 신규 번호도 포함. 신규 + 어르신 모드만 무인증
FA-01 구현 발송 성공 인증 블록 + 5:00 카운트다운 + 재발송 30초 쿨다운 + 입력칸 자동 포커스
FA-02 구현 발송 실패 (결번·수신거부·장애) 입력칸 잠금 + 번호 재확인/보건소 전화 안내
FA-03 구현 유효시간 5분 만료 카운트다운 감춤 + 입력칸 읽기 전용. 재발송이 인증번호 다시 받기로 강조 전환
FA-04 구현 서버 인증번호 불일치 확인을 눌렀을 때만 판정. (2/5번째) 표시. 횟수 제한을 빼면 안 됨 — 6자리는 100만 가지뿐이라 무제한 시도면 인증이 형식적인 절차가 됨
FA-05 구현 서버 5회 실패 → 10분 잠금 확인·재발송 모두 비활성 + 보건소 전화
FA-06 구현 재발송 쿨다운 30초 중 "다시 보내기 (12초 뒤부터)" — 유효시간과 문장을 완전히 분리한 것이 핵심
FA-07 서버 하루 재발송 5회 초과 재발송 영구 비활성 + 보건소 전화
FA-08 구현 인증 성공 입력칸 읽기 전용 + 확인됨(초록) + 재발송 감춤. 이 시점에 자동채움·잠금 해제
FA-09 구현 인증 후 번호를 고침 FE-09와 동일하게 인증 무효화
FA-10 구현 OS 자동 채움 one-time-code로 받되 확인 버튼은 사용자가 눌러야 함

FN · FD — 이름 · 거주지 (10)

코드 상황 화면 처리
FN-01 구현 이름 미입력 제출 시 안내 + 포커스 이동
FN-02 구현 1자 "두 글자 이상 적어주세요"
FN-03 구현 숫자·특수문자 포함 입력 중에는 막지 않음 — 글자가 사라지면 자판 고장으로 인식
FN-04 구현 20자 초과 maxlength로 입력 제한
FN-05 구현 공백만 / 앞뒤 공백 trim() 후 판정. 앞뒤 공백은 조용히 제거
FD-01 구현 동 미선택 안내 + 선택 버튼으로 포커스
FD-02 구현 남동구 거주가 아님 시트 하단 탈출구 → SC-F-04
FD-03 구현 자기 동을 모름 모드별로 문구가 다름 (일반: 직원께 여쭤보세요 / 직원: 신분증을 여쭤보세요)
FD-04 서버 동 목록 로드 실패 정적 폴백 목록 사용. 동 선택이 막히면 폼 전체가 막힘
FD-05 미정 행정동 개편으로 목록 불일치 SC-F-04의 "동이 안 보였다면" 안내가 1차 대응

FC — 동의 (6)

코드 상황 화면 처리
FC-01 구현 필수 동의 미체크로 제출 빠진 항목을 이름으로 나열 + 동의 영역으로 스크롤 + 토스트
FC-02 구현 일부만 동의 모두 동의 자동 해제. 남은 것만 나열
FC-03 구현 일부만 동의 빠진 항목을 모두 나열 (필수 3개 전부 필요)
FC-04 서버 약관 전문 로드 실패 전문을 못 본 상태의 동의는 무효가 될 수 있음. 재시도 + 해당 항목 체크 차단
FC-05 구현 직원이 본인 확인 없이 대신 동의 화면에서 강제할 수 없으므로 기록으로 억제 (대리 작성 기록·시각 저장)
FC-06 미정 동의 후 약관 개정 동의 시점의 약관 버전을 함께 저장해야 재동의 대상을 골라낼 수 있음

FS — 제출 (8)

코드 상황 화면 처리
FS-01 구현 제출 버튼 연타 버튼 잠금 + 스피너. 서버 멱등 처리가 정본
FS-02 구현 제출 중 네트워크 실패 "적으신 내용은 그대로 있습니다" + 다시 보내기 — 입력값 보존을 먼저 말하는 것이 재시도율을 좌우
FS-03 서버 서버 오류 5xx FS-02와 동일 UI. 3회 실패 시 보건소 전화 추가
FS-04 구현 서버 제출 경합 실패로 처리하지 않음. SC-F-03으로 보내며 리드 문구 교체
FS-05 서버 관외 동 코드 (클라이언트 우회) 서버가 화이트리스트로 재검증해 거부 → SC-F-04
FS-06 구현 서버 인증 토큰 만료 후 제출 인증 블록만 초기화. 이름·동·동의는 유지
FS-07 구현 제출 성공 (신규) 회원 생성 + 승인 완료 → SC-F-02. 임시저장 즉시 삭제
FS-08 서버 제출 성공 (기존 회원 연결) 상태값이 달라짐

FR — 완료 · 설치 (6)

코드 상황 화면 처리
FR-01 구현 기기 판별 실패 아이폰·안드로이드 버튼을 같은 크기로 병렬
FR-02 미정 스토어 이동 실패 (인앱 브라우저) "외부 브라우저로 열기" 유도 여부 미정. 문자 링크가 현재 우회로
FR-03 서버 완료 문자 발송 실패 완료 화면은 그대로 둠. 문자는 안전망이지 필수 경로가 아님
FR-04 구현 완료 화면 새로고침·뒤로가기 빈 폼으로 복귀. 같은 번호를 다시 넣으면 FE-06으로 안전하게 수렴
FR-05 미정 앱이 이미 설치됨 딥링크로 로그인 화면까지 보내면 단계가 하나 줄어듦. 스킴 미정
FR-06 구현 본인 폰이라 QR을 찍을 수 없음 QR은 보조 수단. 설치 버튼이 주 경로

FX — 환경 · 세션 (10)

코드 상황 화면 처리
FX-01 구현 모집 기간이 아님 폼을 열지 않고 SC-F-05 + 알림 예약
FX-02 미정 정원 마감 SC-F-05 문구만 교체. 대기 신청 여부 미정
FX-03 미정 지난 기수 URL로 접근 문자로 뿌린 링크는 몇 달 뒤에도 눌립니다. 처리 정책 미정
FX-04 구현 오프라인 상단 띠 + 제출 차단. 입력값은 임시저장돼 있음
FX-05 구현 이탈 후 복귀 (전화 수신 등) 24시간 안이면 복구 배너 + 값 복원 + 지우고 처음부터
FX-06 구현 시트가 열린 채 뒤로가기 페이지를 이탈하지 않고 시트만 닫힘. ESC로도
FX-07 미정 JS 비활성 · 구형 브라우저 최저 지원 버전 미정
FX-08 구현 OS 글자 크기 200% 가로 스크롤 없이 늘어남
FX-09 구현 가로 모드 · 좁은 화면 900px 이하에서 전체 폭. 고정 높이 없음
FX-10 미정 자동완성이 다른 사람 정보를 채움 가족 공용 기기에서 실제로 발생. 완료 화면의 내역 확인이 1차 방어

FP — 직원 모드 (5)

코드 상황 화면 처리
FP-01 구현 직원 모드 진입 폼 맨 아래 링크 → 진한 배너 + 제목 "대리 접수" + 안내 박스. 폼 초기화
FP-02 구현 직원 모드 이탈 배너의 나가기 → 폼 초기화
FP-03 미정 직원 모드로 둔 채 자리를 뜸 N분 무조작 시 자동 해제 필요. 시간 미정
FP-04 구현 연속 접수 다음 분 신청받기 — 모드는 유지, 입력값만 비움
FP-05 미정 직원 식별이 없음 지금은 "직원 모드"라는 사실만 기록. 대리 동의의 책임 소재와 직결

상태 전이표

상태 진입 이름·동·동의 제출 나가는 곳
IDLE 화면 진입 열림 불가 번호 11자리 → CHECKING
CHECKING 번호 완성 열림 불가 조회 결과에 따라 분기
NEW FE-04 열림 가능 제출 → SUBMITTING
NEEDS_OTP FE-05 · FE-07 · 직원 모드 잠김 불가 인증 통과 → VERIFIED
OTP_LOCKED FA-05 잠김 불가 10분 대기 / 보건소 전화
OTP_EXPIRED FA-03 잠김 불가 재발송 → NEEDS_OTP
VERIFIED FA-08 열림 + 자동채움 가능 제출 → SUBMITTING
BLOCKED FE-06 · FE-08 · FE-10 열림(무의미) 불가 SC-F-03 / 전화 / 대기
SUBMITTING 제출 버튼 그대로 잠김 성공 → SC-F-02 / 실패 → 복귀

불변식 3가지 — 이것만 깨지지 않으면 됩니다.

  1. 번호가 바뀌면 무조건 CHECKING 이전으로 돌아간다. 인증·자동채움은 남지 않는다.
  2. NEEDS_OTP 계열에서는 이름·동 필드에 어떤 값도 채워 넣지 않는다.
  3. SUBMITTING 중에는 어떤 입력도 받지 않고, 실패 시 입력값을 하나도 잃지 않는다.
