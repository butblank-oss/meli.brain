1. 목적과 범위

활성 유저 대부분이 3기 리포트를 이미 봤습니다. 11/2 이후 앱에 들어온 256명 중 95%(243명)가 리포트를 열었습니다. 그런데 리포트를 본 243명 중 “4기도 참여하기”로 신청까지 간 사람은 56명, 23%입니다. 신청 버튼이 리포트 맨 아래에 있고 수료증 저장 등 다른 버튼과 겹쳐 있었기 때문입니다(report-3rd-hc 보고 페이지). 이분들을 4기 사전 신청까지 데려오려면 홈에서 4기 신청이 바로 보여야 하므로, 홈 상단 리포트 배너 자리에 4기 신청 배너를 따로 만들어 배포합니다. 재등록 목표는 280명이고, 11/9 기준 사전등록은 137명입니다.

  • 1차 범위 (11/11): 홈 배너 1개, 4기 신청 화면(교실과 신청자 정보 확인)과 약관 시트, 신청 완료, 마감 안내, 전화 문의. 신청 화면은 웹 화면을 앱 안에서 열고, 홈 배너만 앱 화면입니다.
  • 1차 제외 (11/11): 미등록자 안내(S4), 운영자 도구, 개강 안내 문자 발송(보건소가 직접). 신청 내용(S3)은 S2에 합침. 신청 취소는 없음
  • 설계 원칙: 한 화면에 한 가지 일만 둡니다. 모든 화면이 375 × 812에서 스크롤 없이 들어가고, 주요 버튼은 하단에 고정합니다.
  • 범위 밖: 홈 전체를 쉬는 기간 모드로 바꾸는 작업, 멈춘 순위, 활동 잠금, D-day 표기 (이전 핸드오프의 쉬는 기간 화면들)

4. 신청

  • 앱의 새 신청 흐름(S1 → S1-1 약관 → S2)은 홈 배너에서만 시작합니다. 3기 리포트의 “4기도 참여하기”(S7-11)는 기존 방식 그대로 확인 시트 한 번으로 참여하고 약관 동의를 받지 않습니다 11/11 확정
  • 약관 동의 여부 구분: 배너 · 웹 신청서 신청은 약관 3종 동의 기록이 있고, 리포트 버튼 신청은 없습니다. 나중에 동의 받지 않은 분을 골라낼 수 있게 신청 행에 동의 여부(terms_consented)와 진입 경로를 남겨 주세요 11/11 개발 요청
  • 3기 등록 정보(이름, 연락처, 사는 동)를 그대로 써서 신청합니다. 앱에서 입력받지 않습니다. 신청은 지금 쓰는 신청서에 저장합니다.
  • S1에 “남동구에 사는 어르신이 대상이에요”를 한 줄 넣고, 거주지는 앱에서 막지 않고 보건소가 사후 확인합니다.
  • 필수 약관 3종(서비스 이용약관, 개인정보 수집·이용, 인천남동구 보건소 제3자 제공)에 모두 체크해야 신청할 수 있습니다. 문안과 보유 기간은 웹 신청서와 같습니다 11/11 확정

상태 조회 · 신청 · 운영자 처리

GET /cohort/4/apply-status 계산 순서 11/10 확정

  1. banner_enabled = false면 4기 배너를 그리지 않음
  2. 내 user_id, 또는 3기에 등록한 연락처의 phone_hash로 APPLIED 신청이 있으면 APPLIED. 연락처로 찾은 웹 신청은 이때 user_id를 채우고 LINKED_ACCOUNT 기록
  3. 지금이 apply_close_at 이후면 CLOSED
  4. 직전 기수 cohort_member에 이름과 연락처가 모두 있으면 ELIGIBLE
  5. 그 외 NO_PRIOR

응답에 home_banner(4th · report · none)를 함께 내려주면 앱은 판정 로직 없이 그대로 그립니다 제안. report는 APPLIED이면서 3기 리포트 대상자일 때만입니다.

POST /cohort/4/apply 트랜잭션

  1. 같은 Idempotency-Key로 이미 처리했으면 그때 결과를 그대로 돌려줌
  2. 마감이면 410, 살아 있는 신청이 있으면 409. 둘 다 저장 없음
  3. 신청 1행 + 동의 2행 + 문자 2행(APPLY_CONFIRM 즉시, PRE_START_REMINDER 예약) + 이벤트 1행을 한 트랜잭션으로 저장. 하나라도 실패하면 전부 되돌리고 5xx → S1-4 (A-09)
  4. 고유 인덱스 충돌(동시 요청)은 409로 바꿔 응답
  5. 완료 문자는 커밋 뒤 발송 큐로. 발송이 실패해도 신청은 유지하고 재시도

운영자 도구 API 제안 O-21

  1. PATCH /admin/cohort/4/applications/{id}: 이름 · 연락처 · 동 수정, 전후 값을 이벤트에 기록. 연락처가 바뀌면 해시도 다시 계산
  2. 운영자 화면에는 연락처 · 이름으로 검색, 상태 · 경로 · 신청 시각 · 이력이 보여야 함
