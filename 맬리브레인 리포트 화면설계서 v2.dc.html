문서 개요 · 화면 목록
2026년 3월 3일 시작한 치매예방교실 3기가 10월 31일 종료됩니다. 본 리포트는 기수 종료 후 참여자에게 1회 제공되는 최종 회고입니다. 앱 내 웹뷰에서 위에서 아래로 스크롤하며 자신의 8개월을 돌아보고, 마지막 화면에서 수료증을 1:1 정사각형 이미지로 저장하는 흐름입니다. 기수가 이미 끝난 시점의 회고이므로 신규 시작을 유도하는 문구는 넣지 않고, 4기 참여 유도만 CTA로 둡니다.
문구의 정본은 프로토타입입니다
화면에 실제로 찍히는 문구는 맬리브레인 리포트 v3 프로토타입이 정본입니다. 이 문서의 요소표는 그 문구를 옮겨 적고, 값이 어디서 오는지와 없을 때 무엇을 보여줄지를 덧붙인 것입니다. 문구가 서로 다르면 프로토타입을 따르고 이 문서를 고칩니다. 반대로 산식·상수·예외 규칙은 이 문서가 정본이며, 프로토타입의 표시값은 예시입니다.

2-2. 참여일 정의 (F-01) — 초안에서 변경
아래 세 가지 중 하나라도 기록이 있는 날의 합집합. KST 자정 경계로 날짜를 계산하고, 같은 날 여러 건이 있어도 1일로 집계합니다. 사용자별로 다른 기준을 쓰지 않으며 전원 동일 규칙입니다.
① 완료 활동 ≥ 1건 S1 outcome_raw · activity_date_kst
② 로그인 ≥ 1건 S8 login_history · is_success='Y'
③ 걸음 > 0보 S7 step_count · stat_date
참여일 = COUNT(DISTINCT (S1.activity_date_kst ∪ S8.login_date_kst ∪ S7.stat_date))

위에서부터 먼저 맞는 것을 채택합니다. 한때 참여일 단독으로 정리했다가 OR로 되돌렸습니다 — 걸음도 로그인도 없이 활동만 몰아서 한 사용자를 참여일만으로는 건져내지 못하기 때문입니다.

두 조건은 서로를 상당 부분 덮습니다. 참여일 정의(F-01)에 완료 활동이 이미 3항으로 들어가 있어 C가 28명에서 14명으로 줄어드는 것이 그 증거입니다. 그래도 경계에 걸린 사람을 놓치지 않는 쪽을 택했습니다.
활동 건수는 판정에만 씁니다
활동 건수는 A/B/C를 가르는 데만 쓰고 화면 어디에도 노출하지 않습니다. 사용자에게 보이는 숫자는 참여일과 참여율뿐입니다. 두 숫자를 함께 보이면 "왜 수료했는지"를 설명하는 기준이 둘이 되어 증서 표기가 흔들립니다.

판정은 원값으로 합니다. 참여율 반올림값을 쓰면 29.6일이 30%로 올라가 수료로 넘어갑니다.
수료증에 참여율을 함께 찍는 근거
초안은 "참여율 12% · 수료증"이 축하 맥락과 어긋난다는 이유로 참여율을 뺐습니다(P13). 확정안은 "함께한 날 142일 /242일 · 참여율 59%" 형태로 분모를 함께 노출합니다. 분모가 보이면 낮은 퍼센트도 "242일 중 30일"이라는 맥락에서 읽히고, 무엇보다 4기 참여 동기가 됩니다. 분모는 볼드 없이 연회색(#9AA3AD)으로 눌러 시각적 위계를 만듭니다.
A·B 인원은 OR 기준 재집계 대기 중입니다. 기존 641 / 154 / 28은 참여일 단독 기준으로 뽑은 값이라 쓸 수 없습니다. 확정된 것은 C = 14명(1.9%)뿐이고 B는 96~138명 범위로만 파악돼 있습니다. 기수 진행 중이라 20–29일 구간 인원이 10/30까지 30일을 채우면 A는 늘고 B는 줄어듭니다. 탈퇴자는 발급 대상에서 제외합니다.
SECTION 4
공통 예외 처리 코드 (P코드)
각 화면 표의 "설명 / 상태 처리" 열에서 이 코드로 참조합니다. 공통 원칙 네 가지 — ① 모든 화면은 항상 노출한다. 데이터가 없다는 이유로 섹션을 통째로 건너뛰지 않으며, 예외는 없습니다. ② 수치가 없으면 0으로 표기한다(집계는 됐고 값이 0인 경우). ③ 집계 자체가 불가한 경우에만 "–"를 쓴다. ④ 값이 하나뿐이면 그것이 현재 상태다 — 비교 대상이 없다는 이유로 값을 숨기지 않는다.

0과 "–"의 구분이 이 문서에서 가장 자주 틀리는 지점입니다. P02는 언제나 0, P03은 언제나 "–"이며 한 코드가 상황에 따라 둘을 오가지 않습니다.

걸음 미연동만 예외입니다 — "알 수 없다"이므로 원칙상 "–"지만, 화면 전체가 하이픈으로 덮이는 것보다 0 + 안내 한 줄이 낫다고 판단했습니다. 이 예외를 P03에 섞으면 "P03이면 –인가 0인가"를 매번 되묻게 되므로 P16으로 따로 뺐습니다. 연동은 됐지만 한 번도 걷지 않은 경우는 P17이며, 하루 평균의 분모가 0이 되는 지점이라 별도로 셉니다.

최소 데이터 대표값 규칙 (P06 보충)
데이터가 아주 적어도 대표값은 뽑습니다. 예를 들어 화·목에만 참여했고 화가 1회 더 많으면 "화요일"을 대표 요일로 표시합니다. 데이터가 1건뿐이면 그 1건이 대표값입니다. 동점일 때만 아래 규칙을 적용합니다 — 요일·시간은 이른 쪽(월 > 화 > … , 0시 > 1시 > …), 날짜는 가장 최근, 게임은 노션 DB 정렬 순서상 앞. 초안의 "골고루" 표기는 폐기합니다 — 동점이 2개인 경우와 5개인 경우를 같은 단어로 묶어 정보량이 사라지기 때문입니다.

같은 생각이 P04에도 적용됩니다. 측정이 1회뿐이면 "변화를 보여줄 수 없다"가 아니라 그 값이 곧 현재 상태입니다. 실선 바늘로 확정 표기하고 고스트 마커와 변화량만 감춥니다.

다만 아트보드에서 같아 보이는 이 둘은 구현에서 성격이 다릅니다. 아트보드는 8개 화면을 낱장으로 보여주지만 실제 리포트는 오버레이 하나 안에 8개 섹션이 세로로 이어진 단일 스크롤 문서입니다. 닫기 버튼은 오버레이 뷰포트 기준 fixed로 전 구간에 하나만 떠 있고, 스크롤 힌트는 섹션마다 하나씩 있어 스크롤과 함께 지나갑니다. 즉 아트보드의 8개 X는 같은 버튼 하나를 8번 그린 것이며, 8개 힌트는 서로 다른 8개 요소입니다. 닫기 버튼을 섹션 내부 absolute로 구현하면 커버에서 스크롤하는 순간 화면 밖으로 밀려나 오버레이를 닫을 수단이 사라집니다.
⚠ 812를 넘기면 화면을 나눕니다
콘텐츠가 한 화면을 넘으면 카드를 줄이는 대신 화면을 분리합니다. 이 원칙으로 SC-RP-04가 04와 04B로 갈라졌고, SC-RP-05·06은 중복 요소를 덜어내 한 장에 맞췄습니다.

세로로 늘린 아트보드는 목업에서 하단 요소가 화면 밖으로 밀려 검수가 불가능해집니다. 812는 타협 대상이 아닙니다.

SECTION 6
모션 · 인터랙션 명세
가장 중요한 구현 제약 — 스크롤 리빌은 progressive enhancement로
기본 상태가 완성된 리포트여야 합니다. 7개 섹션 전부 보이고 카운터는 최종값입니다. IntersectionObserver가 실제로 콜백을 한 번 준 뒤에야 스크롤 리빌 모드로 강등하고, 그때부터 순차 등장이 동작합니다.

이유 · IO가 발화하지 않는 환경(오프스크린 합성, PNG·PDF 캡처, 일부 웹뷰)에서 리빌을 게이트로 두면 페이지 전체가 빈 화면으로 캡처됩니다. 수료증 1:1 이미지 저장이 이 경로를 타므로 치명적입니다.

구현 · 초기 state = {전 섹션 visible, 카운터 최종값} → IO 첫 콜백에서 {섹션 1만 visible, 카운터 0}으로 1회만 강등 → 이후 스크롤에 따라 순차 리빌. prefers-reduced-motion · IO 미지원 · 섹션 쿼리 실패 시에는 강등하지 않고 완성본을 유지합니다.

성능 함정 — 카운터 동시 실행 금지
여러 카운터를 각자 rAF 루프로 돌리면 프레임당 N회 리렌더가 발생하고, backdrop-filter 표면 약 50개와 겹쳐 메인 스레드가 잠깁니다. 카운터는 단일 rAF 루프에서 모든 값을 갱신하고 한 번의 커밋으로 반영합니다. 여러 값을 동시에 확정해야 할 때도 단일 state 커밋을 씁니다.

폭죽 조각 배열도 최초 1회만 생성해 캐시합니다. 매 렌더 재생성 시 같은 원인으로 라이브락이 발생합니다.
reduced motion — 0으로 죽이지 않습니다
prefers-reduced-motion 시 transform만 제거하고 opacity 페이드는 남깁니다. 전부 끄면 요소가 툭 나타나 오히려 인지 부하가 커집니다.

animation: none · transform: none · transition-property: opacity · duration .2s · delay 0

금지 · transition: all / scale(0) 진입(→ scale .94 + opacity) / UI에 ease-in.
